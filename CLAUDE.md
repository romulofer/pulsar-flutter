# pulsar-flutter

## Visão Geral do Projeto

Support for Dart and Flutter on the code editor Pulsar

## Fases do Projeto

### Fase 1: Planejamento

observe todos os pacotes em ../references. analise as documentações. vamos usar eles como base para construir um add on moderno e atualizado para adicionar suporte a dart e flutter no pulsar


### Fase 2: Documentação

Fazer os documentos de spec e plan, para orientar todo o desenvolvimento do projeto


### Fase 3: Execução

construir o código de acordo com a documentação gerada acima


### Fase 4: Teste

instalar o add on em ambiente local, no pulsar, e aguardar testes do usuário


### Fase 5: Publicação

publicar no pulsar e no github. remote: git@github.com:romulofer/pulsar-flutter.git


## Critérios de Aceite

- faça testes unitários e de integração
- faça testes e2e e/ou de instrumentação
- use boas práticas do desenvolvimento de software
- código deve ser separado em arquivos e pastas
- arquivos de teste devem terminar com test.extensão, de acordo com a case exigida pela linguagem
- o código deve ser sempre modular e reutilizável
- ao se deparar com a construção de uma nova feature, ou correção de bug ou documentação proceda com spec, plan e execução 
- readme deve estar em português e inglês. português antes do inglês. use imagens, prints, identidade visual, emojis, para tornar visualmente agradável

## O Que Não Fazer

- não fazer commits e pushes a não ser que o usuário peça
- quando fizer commits e pushes, o usuário deve ser o único autor, o agente de IA nunca deve assumir autoria ou co-autoria
- nunca commitar dados sensíveis
- nunca, em hipótese alguma, usar em dashes
